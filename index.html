QUESTION 4 (SPECIAL FOCUS)

Explain Structure of Distributed Shared Memory (DSM).

Course Outcome: CO-03 Bloom's Level: BL2 6 Marks

1. Definition & Overview of DSM

Distributed Shared Memory (DSM) is an abstraction used in distributed systems that allows physically separate computing nodes (which only have their own private local memory and communicate via a network) to share a single, unified logical address space. Even though there is no physically shared memory hardware, the DSM runtime layer creates an illusion for application programmers that all processes are reading from and writing to a common global memory.

Hinglish Explanation (Introduction):
Distributed Shared Memory (DSM) ek aisa smart concept (abstraction) hai jisme alag-alag computers (nodes) ke paas apni khud ki private local RAM hoti hai, par DSM software un sabko mila kar ek Single Global Shared Memory ka illusion (ehsaas) deta hai. Programmer ko lagta hai ki wo ek hi common memory me read/write kar raha hai, jabki background me DSM khud network messages ke through data transfer sambhalta hai!

3. Three Approaches to Structure the Shared Memory Space in DSM

The structure of the shared memory space defines how the global shared data is organized, laid out, and accessed by processes. In Distributed Systems, the shared memory space of a DSM system is structured in three primary ways:

Figure 4.2: Three Structural Models of Shared Memory Space in DSM
Structure 1
1. No Structuring (Unstructured / Byte-Stream / Page-Based)
  • Concept: The shared memory space is treated simply as an unstructured linear array of bytes or words, identical to traditional physical RAM.
  • Mechanism: The memory is divided into fixed-size equal blocks called Pages (e.g., 1 KB, 4 KB, or 8 KB) managed by the Operating System's Virtual Memory (MMU) hardware using page faults.
  • Advantage: Allows any standard sequential/shared-memory program to run without changing data types.
  • Disadvantage: Suffers from False Sharing because unrelated variables may sit on the same large page.
  • Example Systems: IVY, Mirage, Clouds.
Hinglish Me Samjho:
Isme shared memory ko bilkul normal RAM ki tarah ek seedhi byte-array (linear memory) maana jata hai. Isko barabar size ke Fixed Pages (jaise 4KB) me baant dete hain. Jab kisi process ko data chahiye hota hai aur wo local memory me nahi milta, toh Page Fault aata hai aur network se poora page uth kar aa jata hai.
Structure 2
2. Structuring by Data Type (Shared Variables)
  • Concept: Instead of raw pages, the shared memory is structured as a collection of language-level shared variables, structs, or data structures declared with special keywords (like shared).
  • Mechanism: Granularity is variable-sized—matching the exact data type being shared. Only the modified variable is transmitted over the network.
  • Advantage: Completely eliminates or drastically reduces False Sharing and reduces network traffic.
  • Example Systems: Munin, Midway.
Hinglish Me Samjho:
Poore 4KB ke page ko bhejne ke bajaye, yahan memory ko Program Variables aur Data Types (jaise shared int x, arrays, structs) ke hisaab se structure kiya jata hai. Fayda ye hai ki agar ek chota variable badla, toh sirf wahi network par jayega, jisse False Sharing ki problem khatam ho jati hai!
Structure 3
3. Structuring as a Database / Object-Based DSM
  • Concept: The shared memory space is structured Either as an associative database of tuples (Tuple Space) or as a collection of encapsulated Objects.
  • Mechanism: Processes cannot directly touch raw memory addresses. In Linda, processes use out(), in(), and rd() on tuples. In Orca, processes invoke synchronized methods on shared objects.
  • Advantage: Automatic synchronization and clean modular protection.
  • Example Systems: Linda (Tuple Space), Orca (Shared Objects).
Hinglish Me Samjho:
Is model me memory ko ek Database (Tuple Space) ya OOP Objects ki tarah banaya jata hai. Koi bhi process seedha memory address chhed nahi sakta; data access karne ke liye Object ke functions (methods) call karne padte hain (jaise Orca me) ya Tuple queries (jaise Linda me) lagani padti hain.
Feature / Parameter 1. Unstructured (Page-Based) 2. Structured by Data-Type 3. Object / Database Structured
Basic Unit (Granularity) Fixed-size OS Page (e.g., 4 KB) Shared Variables / Data Structures Encapsulated Objects or Tuples
Access Method Direct Memory Read/Write via MMU Compiler-assisted Variable Access Method Invocation / Tuple Operations
False Sharing Risk High (Due to large fixed pages) Low / Eliminated None (Object-level encapsulation)
Classic Examples IVY, Mirage Munin, Midway Linda (Tuples), Orca (Objects)

Q1. Explain desirable features of a good Distributed File System (DFS).

CO-03 • BL1 • 6 Marks

A Distributed File System (DFS) enables programs to store and access remote files across a computer network exactly as if they were local files. A well-designed DFS must possess the following desirable features:

1. Transparency (Access, Location, Migration, Replication): Users should not need to know where a file is physically located or whether it has moved to another server.
2. User Mobility: Users should be able to log in from any node in the network and see their exact same home directory and file environment.
3. Performance & Caching: File access latency should be comparable to a local disk using client-side and server-side caching.
4. Fault Tolerance & High Availability: If one file server crashes, replicated file copies and stateless servers should keep the system running smoothly.
5. Scalability & Heterogeneity: The system should scale from a few machines to thousands and support different OS platforms (Linux, Windows, macOS).
6. Security & Data Integrity: Concurrent updates must be synchronized (locking), and unauthorized users must be blocked via authentication and ACLs.
Hinglish Explanation (Q1 - DFS Features):
Ek acche Distributed File System (jaise Google Drive ya NFS) ki sabse badi khaasiyat hoti hai Transparency—matlab user ko pata hi nahi chalna chahiye ki file uske local computer par hai ya kisi remote server par. Iske alawa User Mobility (kisi bhi PC se login karo toh same files dikhein), Fault Tolerance (ek server down ho toh backup server se file mil jaye), aur Caching (bar-bar network se mangwane ke bajaye local cache se fast file khule) hona bahut zaroori hai.

Q2. What is Deadlock? Explain necessary conditions for deadlock.

CO-03 • BL2 • 6 Marks

Deadlock Definition: A deadlock is a permanent blocking state in a distributed or operating system where a set of two or more processes are waiting indefinitely for resources that are currently held by other processes within the same waiting set. Because none of the processes can proceed or release their held resources, the entire group remains stuck forever.

Figure: Circular Wait Cycle causing Deadlock between Process P1 and Process P2

Coffman's Four Necessary Conditions for Deadlock (All 4 must hold simultaneously):

1. Mutual Exclusion: At least one resource must be held in a non-sharable (exclusive) mode; only one process can use the resource at any given time.
2. Hold and Wait: A process must be currently holding at least one resource while simultaneously waiting to acquire additional resources held by other processes.
3. No Preemption: Resources cannot be forcibly taken away (preempted) from a process; they can only be released voluntarily by the holding process after it finishes its task.
4. Circular Wait: A closed chain (cycle) of processes exists such that $P_1$ is waiting for a resource held by $P_2$, $P_2$ is waiting for $P_3$, ..., and $P_n$ is waiting for a resource held by $P_1$.
Hinglish Explanation (Q2 - Deadlock & 4 Conditions):
Deadlock ek aisi situation hai jahan do ya do se zyada processes ek-dusre ke resources ke liye hamesha ke liye wait karte reh jate hain (jaise P1 ke paas R1 hai aur use R2 chahiye, jabki P2 ke paas R2 hai aur use R1 chahiye).
Deadlock tabhi hota hai jab ye 4 conditions ek saath sach hon: 1) Mutual Exclusion (Ek waqt par ek hi process resource use kar sake), 2) Hold and Wait (Ek resource pakad kar dusre ka intezaar karna), 3) No Preemption (Zabardasti resource छीना na ja sake), aur 4) Circular Wait (Waiting ka ek gol chakkar/cycle ban jaye).

Q3. Explain Remote Procedure Call (RPC) Mechanism with neat diagram.

CO-03 / CO-02 • BL1 • 6 Marks

Remote Procedure Call (RPC) is a powerful high-level communication paradigm that enables a client process on one machine to call a procedure/function on a remote server machine across a network just as if it were a normal local function call, hiding all underlying socket and network complexities.

Step-by-Step Working of RPC:

  1. Client Call: The client process invokes a normal local procedure call to the Client Stub passing parameters on the stack.
  2. Parameter Marshaling: The Client Stub packs the procedure identifier and arguments into a standard network message format (Marshaling) and asks the local RPCRuntime to transmit it.
  3. Network Transmission: The Client OS sends the request packet over the network to the remote Server OS.
  4. Unmarshaling at Server Stub: The Server OS hands the packet to the Server Stub, which unpacks (unmarshals) the parameters.
  5. Procedure Execution & Reply: The Server Stub invokes the actual remote procedure. Once executed, the return result follows the exact reverse path back to the client!
Hinglish Explanation (Q3 - RPC Mechanism):
RPC ka main kaam hai remote machine par rakhe function ko aise call karna jaise wo humare local computer par hi ho! Isme do Stubs (Dalal/Translators) kaam karte hain:
1) Jab Client function call karta hai, toh Client Stub parameters ko pack (Marshaling) karke message banata hai aur network par bhej deta hai.
2) Server side par Server Stub us message ko kholta hai (Unmarshaling) aur asli Server Function ko call karke result wapas usi raaste se Client ko lauta deta hai.

Q5. Explain Design and Implementation Issues of Distributed Shared Memory (DSM).

CO-03 • BL1 • 6 Marks

Designing an efficient Distributed Shared Memory (DSM) system requires resolving several critical architectural and performance issues:

1. Granularity (Block Size) & False Sharing: Choosing the right size of the shared memory unit (word, page, or object). Large pages reduce page table overhead but cause False Sharing (when two unrelated variables reside on the same page and accessed by two different nodes simultaneously).
2. Structure of Shared Memory Space: Deciding whether memory should be unstructured (byte array/pages), structured by variables/data types, or structured as objects/tuples (as detailed in Q4).
3. Memory Coherence & Consistency Models: Defining rules for when updates made by one process become visible to other processes (e.g., Strict, Sequential, Causal, Release, or Weak Consistency).
4. Replication & Coherence Protocols: To improve read performance, shared blocks are replicated across nodes. Updates are managed using either Write-Invalidate (invalidating other copies before writing) or Write-Update (broadcasting updated data to all copies).
5. Thrashing Control: Thrashing happens when a memory page ping-pongs back and forth rapidly between two nodes competing for access. Resolved by pinning pages for a minimum time slice ($T$).
6. Replacement Strategy: When a node's local memory cache becomes full, it must evict a page (using LRU or sending a dirty page back to its owner node rather than discarding it).
Hinglish Explanation (Q5 - DSM Design Issues):
DSM banate waqt 5-6 main challenges aate hain:
• Granularity & False Sharing: Memory block kitna bada rakhein? Agar page bahut bada rakha, toh alag-alag variables ek hi page me fas jayenge jise False Sharing kehte hain.
• Consistency Model: Ek node ne write kiya toh dusre node ko kab aur kis order me wo update dikhna chahiye?
• Thrashing: Jab do nodes ek hi page ko baar-baar ek-dusre se cheente hain (ping-pong effect), toh system slow ho jata hai—ise Thrashing kehte hain.
